## 1. 目的と非目的

### 1-1. 目的

WebUI（イベントJSON工場）を**使用感込みで完成宣言に持っていく**。あわせて
export（共通中間形式）から**第3エンジンRen'Pyへの出力可能性を証明**し、
Tyrano・Godotに続く汎用制作工場への格上げ根拠を取る。

工事は2本：

- **工事D（Eagle D&D画像割当）**：カードUIの割当スロットへEagleから
  画像を直接ドラッグ&ドロップで割当可能にする。先輩裁定により
  v2送り玉から**v1完成条件へ昇格**
- **工事R（events_to_renpy アダプタ）**：export一式→Ren'Pyプロジェクトへの
  変換アダプタ（CLI・決定論）。合格線はスモークテスト1点のみ（§1-3）

### 1-2. 非目的（やらないこと・41番§2の教訓の直接適用）

- **Ren'Py側の磨き込み**：choice分岐・音声再生・効果（apply）消費・
  変数補間の実動・セーブ/ギャラリー等は全て対象外。
  「出力契約の証明」と「受け側の磨き込み」を分ける（掟・41番§2）
- **store-simの改修**：テストベンチであって磨く対象ではない（41番§2厳守）。
  使用感実走の受け皿として現状のまま使う
- **Eagle API連携（サムネ一覧のWebUI内表示）**：構想メモ③案は工数一段重。
  D&Dで足りるため今回見送り（先輩承認済み・v2玉として温存）
- **シナリオの中身の審査**：使用感実走は「UIの動作と作品完成までの
  フロー」の検証であり、台本の質は問わない（先輩裁定C）
- **その場画像生成・感情タグ×立ち絵連動**：v2玉のまま変更なし

### 1-3. Ren'Pyスモークテストの合格線（先輩裁定B・これ以上を求めない）

**「export→アダプタ→Ren'Pyで起動→イラスト付きでシナリオが表示される」**

- 長さ不問。choice/音声/効果/変数の動作は問わない
- 背景（stage.bg）が画面に出て、台詞・地の文が読み進められれば合格
- 実需の背景：本ツールの試用希望者がRen'Pyユーザー（先輩情報）。
  第3エンジン開通＝配布・共同利用の入口が開く

## 3. 工事D：Eagle D&D画像割当（先輩方式承認済み 2026-07-22）

### 3-1. 方式（確定）

EagleアプリからカードUIの割当スロット（背景／立ち絵枠）へ画像をドラッグ
→ブラウザがOSファイルドロップとして受領→FastAPIへアップロード→

1. 作品assets配下へコピー（**バックアップ・既存ファイル無改変**。
   同名衝突時は上書きせず採番退避）
2. 画像ID自動採番＋レジストリ登録
3. 該当stageステップ＝台本md `##舞台:` 行へ書き戻し
   （**mdが正・独自メタ不保持**の柵＝DES-0002§2-9をそのまま継承）

Eagle APIは使わない。Eagleの「ドラッグでファイル実体を渡せる」挙動に
乗る素直な方式。Eagleを介さない普通のエクスプローラD&Dも同じ経路で
受かる（実装上の区別なし＝おまけで汎用化）。

### 3-2. ID採番規則（提案・Step D1で現物確認込み確定）

- 基本：**元ファイル名ベースの正規化**（拡張子除去・小文字化・
  空白/記号→`_`・日本語はそのまま可か要現物確認→不可ならローマ字化は
  せず `img_` プレフィクス＋連番へフォールバック）
- 衝突時：`_2` `_3` サフィックス連番
- 根拠：Eagle側の整理名がIDに残る方が人間の目視照合が楽。
  完全連番は照合コストが高い
- **要現物確認事項（クロB・Step D1冒頭）**：EagleドラッグでOSに渡る
  ファイル名の実態（Eagle内部名か元名か）／日本語ファイル名の
  レジストリ・lint・Godot読込の通り具合。結果次第で規則を追い確定

### 3-3. 受け入れ制約

- 形式：png / jpg / webp（それ以外は明示エラー・黙って捨てない）
- 割当先文脈で振り分け：背景スロットへのドロップ→bg登録・
  立ち絵スロット→立ち絵登録。振り分けはドロップ先UIが決める
  （ファイル内容からの自動判定はしない・決定論）
- 巨大ファイルは警告のみ（FAILにしない。額装・縮小は本工事のスコープ外）

### 3-4. UI要件（最小）

- 割当スロットにドロップゾーン表示（ドラッグオーバーでハイライト）
- ドロップ→アップロード進捗→サムネ即時反映→md書き戻し完了表示
- 失敗時は赤表示＋理由（形式不正・書込失敗等）。**黙って失敗しない**
  （掟9の系：見えない失敗が誤認の温床）

## 4. 工事R：events_to_renpy アダプタ

### 4-1. 設計の構え（掟11適用）

- **export一式＝共通中間形式**。エンジン別アダプタを外付けする構え。
  Tyrano（処女作・レガシー）／Godot（store-sim・主力）／Ren'Py（本工事）
- 置き場：`~/novel_mvp/tools/events_to_renpy.py`（CLI単体実行・決定論・
  webuiからの呼び出し配線は**任意**＝スモーク合格後に判断）
- 入力：export/{作品名}/ 一式（events/*.json・images.json・
  voice/*.ogg・manifest.json）
- 出力：Ren'Pyプロジェクト骨格（scriptファイル＋images配置）

### 4-2. 変換対応（スモーク限定・最小写像）

| イベントJSON | Ren'Py出力（想定・Step R0で現物確認後に凍結） |
|---|---|
| stage.bg | 背景表示文（scene相当）＋画像ファイルをimages配下へ配置 |
| stage.slots | v1では**表示しなくても合格**（背景＋テキストで合格線は満たせる）。写像が安価なら表示（show相当）まで実装可・R0調査後に判断 |
| line（speaker＋text） | 話者付き台詞文（character定義＋say相当） |
| narration | 地の文（narrator say相当） |
| choice | **平文化して流す or 先頭選択肢固定で直進**（分岐実動は対象外・R0後に安価な方を選ぶ） |
| apply / set_flags / 変数補間 {var} | 消費しない。補間は「そのまま文字列表示」か「除去」のどちらかをR0後に決定（黙って化けさせない） |
| voice | 配置のみ（再生配線は対象外） |

- 未対応要素は**警告付きスキップ**（DES-0002§4-2と同原則：
  黙って化けるのが一番怖い）
- 梱包形式（プロジェクトのディレクトリ構造・エンコーディング・
  ファイル命名制約）は**受け手現物で確認してから仕様化**（掟11：
  中身のスキーマだけでなく包み方まで契約に書く）

### 4-3. Step R0：Ren'Py受け手現物調査（施工より先・非交渉）

クロB（novel_mvpの家）で実施。調査項目：

1. Ren'Py SDKの入手・配置（WSL側で取得。**起動確認の最終判定は
   先輩Windows実機**——配布形態がWindowsユーザー向けのため）
2. 最小プロジェクトの現物構造：`game/script.rpy`・`game/images/`・
   options/gui等の必須ファイル・プロジェクト認識の条件
3. 記法の現物契約：label開始点・scene/show/say・character定義・
   日本語テキストのエンコーディング（UTF-8 BOM有無等）
4. 画像参照規則：ファイル名→画像タグの自動対応・対応形式（webp可否）・
   ファイル名の文字制約（日本語可否＝§3-2の採番規則にも跳ねる）
5. 起動手順の最短経路：SDKランチャー経由／コマンドライン起動の実測
6. **実測レポート提出→司令塔が§4-2を追い確定→アダプタ施工着手**

私（司令塔）の一般知識で§4-2の想定は書けるが、**現物確認前に凍結しない**。
梱包形式不一致で丸1日誤認した実例（DEC-0007・41番§1）の直接教訓。

## 5. 使用感1周実走の検収手順（先輩実機）

- 弾：既存台本（quality_line_a 等・**中身は審査しない**）
- 経路：台本読込→カードで行編集1件以上→**EagleからD&Dで背景1枚
  以上を実割当**→音声（差分生成含む）→lint PASS→export→
  store-sim手動コピー→実機再生
- 検収は**指紋で取る**（掟9）：再生されたシーン冒頭の内容・割当した
  画像IDがmd `##舞台:` 行に書き戻っているか・エラー有無を事実で確認
- 1手ずつ結果確認（掟10）：D&D→md書き戻し確認→次工程。
  横道が入っても突合結果を見てから進む
- 引っかかりは全件記録→その場で「即修正／v2送り」を先輩と裁定

- **Step D2**：D&Dフロント（ドロップゾーン・進捗・即時反映・エラー表示）。
  合格：先輩実機でEagle→スロットD&D→サムネ反映→md書き戻しの指紋確認

## 追記：§4-2確定版（r1.1・R0実測反映・司令塔裁定 2026-07-22）

- プロジェクト骨格：renpy_probeのgame/一式（script.rpy除く）を
  アダプタ内にvendor同梱し丸ごとコピー。script.rpyのみ生成
  （gui.rpy要否問題は同梱方式により解消）
- 画像ID規約：小文字ASCII正規化で全パイプライン統一。
  非ASCIIはimg_連番フォールバック（§3-2の採番規則としても確定）
- stage.bg → scene文＋画像をgame/images/へ配置（小文字ASCII名）
- stage.slots → show文（配列長 1=center / 2=at left・at right）。
  合格線外のbest-effort実装
- line → Character定義＋say。narration → 地の文say
- choice → ネイティブmenu＋jump（event_id=label）。合格線外
- apply/set_flags → 警告付きスキップ（消費しない）
- 変数補間{var} → {{var}}エスケープでリテラル表示
  （Ren'Pyテキストタグ構文との衝突回避・黙って化けさせない）
- voice → game/audio/voice/へ配置のみ（再生配線なし）
- エンコーディング：UTF-8（BOM無し。R0-3で両対応実測済み）
- 未知step型・未対応要素は警告付きスキップ（黙って落とさない）
