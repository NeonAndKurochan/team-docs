## §0 思想（非交渉・全実装判断の上位基準）

1. **運用時AI不在**。生成・選別・仕上げの全工程はローカルPython＋ffmpegの決定論コードで動く。AIの出番は開発と修理の時だけ。API呼び出し・ネット通信・課金要素はゼロ。
2. **人間の判断が最終権限**。数値（sharp等）は足切り道具。選ぶのは先輩の目と耳。ツールは判断を代行せず、判断の材料を運ぶ。
3. **中身非依存**。本ツールはプロンプト・画像・動画の中身を解釈しない実行管理ランナーである。プリセット（何を撃つか）の中身は先輩の資産で、箱＝ツールは中身を運ぶだけ。
4. **novel_mvp必勝パターンの動画版**。手動1本（S0系）→型固定（KNW-0001）→WebUI化（本書）。型は既に実測で確定済み——本書は新発明をせず、KNW-0001の型をUIに焼き込む。
5. **silent失敗の根絶**。欠け・不整合・失敗は必ず発射前または発生時に人間へ会いに来る（エラー可視化・警告バナー・状態バッジ）。黙って落ちる/黙って捨てる実装は欠陥として扱う。

## §3 アーキテクチャ

- **構成**: novel_mvp実績型を踏襲——FastAPIバックエンド＋Vite+React+TSフロント＋subprocess薄層。リポジトリ `~/video-webui/`（新設・git init初手）
- **ポート**: 既定8791（起動時に使用中検査→衝突なら明示エラーで停止。7860/8767/41595等の既存サービスと重複禁止）
- **キュー実行はサーバ側常駐**: ブラウザはビューにすぎない。実行状態はブラウザ切断と無関係に継続
- **状態永続**: SQLite単一ファイル（キュー行・弾メタ・選別チェック）。ただし**成果物の正はファイル実在**（novel_mvpの掟）——起動時に出力ディレクトリを走査してDBと突合し、不整合はDB側を実在に合わせて修復＋画面に修復報告バナー
- **生成呼び出し**: S0系で実績のある既存配線（Wan2GP呼び出し経路・ジョブJSON方式）を流用する。実体はKNW-0001と既存資産（wan2gp-line系）の現物調査で確定（実装Step0）。**Wan2GP本体・本体configの変更は禁止**（従来柵）
- **ffmpeg/音声/FCPXML**: s15_fcpxml.py（744行・masterマージ済み）とS0.11〜S0.13の音響資産を流用。video-webuiへはコピーでなく参照または明示コピー＋出所コメント（二重管理を作る場合は同期手順をREADMEに明記）
- **ディレクトリ案**:
  - `~/video-webui/server/`（FastAPI）・`~/video-webui/app/`（フロント）
  - `~/video-webui/data/recipes/`（レシピJSON）・`data/presets/`（プリセットJSON）
  - `~/video-webui/docs/`（本書コピー・モック2本・README）
  - 生成出力はWindows側の既存動画作業領域を継承（実パスはStep0で現行運用を確認して設定ファイルに1箇所定義。コードへの直書き禁止）

## §4 データモデル

### 4-1 レシピ（どう撃つか）
```
recipe {
  id, name, engine: "wan22" | "ltx",
  locked: bool,            // 🔒原本=KNW-0001正典。編集不可・「複製して編集」のみ
  frames, mult, nag_scale,
  shots_default,           // 発射数既定（ループ2・多段4=EasyWan22体感値。Wan2GP実測で書換可）
  end_default: "same" | "diff" | "none",
  loras: [ { name, weight, high_file, low_file, note } ],
  prompt_frame_pos,        // 共通枠＋{preset}差し込み位置
  prompt_frame_neg,
  pw_windows,              // 多段時の窓構成（窓ごとのプリセット割当規則）
}
```
- 🔒原本の初期投入はKNW-0001の確定値から転記（wan22_ループ_標準／wan22_多段PW_フィニッシュ／ltx_静寄り_長尺余韻の3本＋テスト用_低負荷）。転記元の項番号をレシピJSON内にコメント記録
- ネガティブの型: 破綻防止系＋candlelight封殺＋成人柵（loli/young/child/minor/kid/small/short）はレシピ共通枠に恒久焼き込み。**ポジにmature/adult/tallは入れない**（キャラ崩壊柵・チーム法典どおり）

### 4-2 プリセット（何を撃つか）
```
preset { id, name, positive, negative, pw_split: "none" | "half" }
```
- 全部マイデータ（🔒なし）。初期枠3つ空で用意（ピストン_標準／フィニッシュ_差分用／フィニッシュ_LoRA任せ）。中身は先輩がEasyWan22定型をコピペ登録
- ツールはプリセット本文を解釈・検査・書換しない（中身非依存原則）。文字数上限等の機械検査のみ

### 4-3 キュー行
```
queue_row {
  id, order, start_image, end_image?, end_mode: "same"|"diff"|"none",
  recipe_id, preset_id, shots, override_prompt?,   // 行だけの上書き（普段空欄）
  status: "waiting"|"generating"|"done"|"stopped"|"error",
  progress: {done_shots, total_shots}, error_detail?
}
```
- 待機行は常時編集可。generating/done/errorはロック（表示のみ）
- 完成プロンプト＝レシピ共通枠＋プリセット本文（＋行上書き）。行の✎で答え合わせプレビュー（合成結果をそのまま表示）

### 4-4 弾（生成結果）
```
clip { id, queue_row_id, seed, file, sharp, motion, rank_in_batch,
       cutoff: "pass"|"cut", picked: bool, retry_of? }
```
- 足切りで"cut"になってもファイルは削除しない（出力削除禁止）。既定フィルタで非表示になるだけで、フィルタ切替で全弾見える

## §5 画面仕様（モックv4準拠・差分と補足のみ記す）

### 5-1 撃つ
- 2レーンD&D: STARTレーン（数百枚一気・連番自動整列・end既定「＝start」）／ENDレーン（差分時のみ・連番自動マッチ・**枚数不一致は警告バナー＋末尾行end空を明示**）
- 新規行の既定値パネル: レシピ（発射数既定表示付き）・プリセット・足切り3段
- キュー表: チェック・並べ替え（ドラッグ）・start/endサムネ・end3値セレクト・レシピDD・プリセットDD・発射数直接編集・状態・✎詳細・🗑
- 一括変更バー: **明示チェック行にのみ**作用（誤爆防止）。レシピ/プリセット/発射数一括・選択行削除
- end列修正3段構え: ドラッグ交換／⇧⇩シフト／↺再マッチ
- **▶キュー実行ボタン必須（自動開始禁止）**→①GPU排他チェック（Forge/ComfyUI/EasyWan22等の起動検知＝nvidia-smi＋プロセス実測。検知時は発射拒否＋何が動いてるか表示）→②多段行のみペア確認モーダル1枚（ループ/なし行は確認スキップ）→③発射
- 実行中の追加行は末尾自動合流。全中止は確認ダイアログ経由。行単位の一時停止（現shotの完了を待って停止）
- キュー統計: 完了/生成中/待機・総弾数・想定所要（1発あたり実測平均から算出・初回は仮値表示と明記）

### 5-2 選ぶ
- キュー/シーン単位の折りたたみ束＋**遅延読み込み（300本規模前提・サムネは静止画・開いた束だけロード）**
- クリックで1本だけ再生（同時多重再生しない）
- 順位バッジ: **同バッチ内相対のみ**（sharp・motion。絶対基準なしの旨を日本語解説の折りたたみで常設）
- 足切り3段（キュー行ごとの設定・選ぶ画面で変更も可）:
  - ゆるめ（既定・推奨）: 明らかな失敗弾のみ非表示＝真っ暗（黒フレーム率閾値）・尺ズレ（期待フレーム数との乖離）
  - ふつう: 上記＋同バッチ下位（sharp下位一定割合）も非表示
  - なし: 全弾表示
  - 実装閾値はStep実測で確定し、設定ファイル化（コード直書き禁止）
- チェック→「選んだ素材で仕上げる」。⚙調整して再生成（§5-4）
- **スマホ最低限対応（本画面のみ）**: 縦幅狭でもサムネグリッド・チェック・再生・足切り切替が破綻しないレスポンシブ（朝ベッドから選別する用途）。フル最適化・他画面のスマホ対応はv1.1送り

### 5-3 仕上げ（モーダル）
- 選択弾に音響（喘ぎ帯方式＋SE点打ち）を適用しFCPXMLを書き出す
- 出力三択: シーンごと個別FCPXML／全シーン連結1本／両方
- 「全工程ローカル・AI/API/ネット不使用」バッジ常設
- 完了時に出力フルパス表示（先輩がDaVinciで開く導線）
- 音響の型はKNW-0001どおり: 帯方式（弱→中→強→絶頂・切替2秒クロスフェード）・SE点打ち（S0.11のonset検出流用・50%基準）・音声2ch統一。**v1の帯区間指定は手動（開始時点指定）でよい**——段階自動化はスコープ外（S0.14裁定踏襲）

### 5-4 調整して再生成（モーダル）
- seed（固定=同条件比較／空欄=ランダム）・LoRA weight・mult・発射数を変更して撃ち直し
- 撃ち直しはキュー末尾に新行として合流（元弾は比較用に残置）
- 「📋 レシピとして保存」: 現在値をマイレシピ（🔒なし）として昇格保存＝良設定の型還流

### 5-5 レシピ／プリセット（タブ）
- レシピ一覧＋詳細。🔒原本は全欄disabled＋バナー「編集は複製して編集から」
- LoRAセクション（補足モックが正）:
  - カード: 表示名・実在✓/⚠・H/L両ファイル名（フルパス折りたたみ）・weight・罠警告（例: Fused 0.3超は顔変化——警告文はKNW-0001罠集から転記）・🗑
  - 片側欠け＝赤エラー「発射前に止まる（silent失敗させない）」＋対処案内（ファイルを戻すか外す）
  - **追加は在庫プルダウンのみ・手打ち禁止**。スキャン先＝商用ホワイトリスト4フォルダ（Download／Nashikone-I2v／Nashikone-I2vWan21／Nsfw）＋DL済みLTX射精2本のみ。ホワイトリスト外は一覧に出ない＝商用の柵をUIに焼き込み
  - H/Lペアは1操作で両側投入（ペア対応規則・例外symlink等はKNW-0001の現物確認で転記）
  - スキャン先パスは設定ファイル1箇所定義。追加は司令塔裁定＋Civitai商用フラグ検問とセット（従来掟）
- プリセット: 名前＋ポジ＋ネガ＋PW窓割り方（分割しない／前半後半を「---」区切り）

## §6 生成実行の仕様

- キューは直列実行（GPU1枚前提）。行内はshot単位で直列
- 発射前検査（行単位・全項目パスで発射）: start/end画像実在→レシピ実在→プリセット実在→LoRA H/L全ファイル実在→GPU排他。**どれか欠けたらその行をerrorにして次行へは進まず停止**（黙って飛ばさない。停止理由を行に表示）
- 生成失敗shot: リトライ1回→なお失敗なら行をerrorで停止・詳細表示。他行を勝手に続行しない（先輩が状況を見て再開判断）
- 進捗はshot完了ごとにDB更新＋画面ポーリング反映。「ブラウザを閉じてもサーバ側で続行します」を実行中ヘッダに常設
- 想定所要時間は直近実測の移動平均で更新

## §7 選別・指標の仕様

- sharp: S0系実装の流用（同バッチ内相対比較専用）。motion: 参考値（カメラ揺れ混入の注記を画面に残す）
- 指標計算は生成完了時に非同期実行（選ぶ画面のロードをブロックしない）
- 足切り判定は§5-2の3段定義。cut弾もファイル・DB・画面フィルタで完全に追跡可能

## §8 仕上げ・FCPXMLの仕様

- 8-1 変換器はs15_fcpxml.py系譜を流用。DaVinci Resolve 21無料版で開ける形式を維持（Media Offlineなし・音声トラック配置・実機検分S1合格の型）
- 8-2 リタイムはスコープ外（DaVinci手当て・工程の最後、の裁定どおり）。dip等のトランジションはDEC-0025の2種（dip=シーン切替／crossfade=体位替え）を連結時に適用
- 8-3 出力: 個別／連結／両方。連結順は選ぶ画面の表示順が正
- 8-4 **設計入力3点（records/s15/音声A2メモ・実装の正）**:
  1. 素材出口のffmpegは`-map 0:v`で映像に無音音声ストリームを残さない（A2問題の根・内蔵無音AAC混入の再発防止）
  2. 音声クリップと映像クリップの尺関係を仕様として明文化する（実装Stepで本メモの記載どおりに確定・帯のトリム規則含む）
  3. Probe（ffprobe1回でhas_audio/channels/rate/frames取得）を発射前・仕上げ前の足切り判定に再利用
- 8-5 検収必須: 音声2ch統一＋Windows標準プレイヤー再生確認（寛容プレイヤーでは検出不能の罠・KNW-0001）

6. 出力削除禁止（足切り・調整再生成でも元弾残置）
7. silent失敗禁止（全fetch/全subprocessの失敗は画面到達）
