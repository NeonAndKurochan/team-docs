# 音声差分結線工事 設計書 r1

- 出典: 脚本authoring現物調査（2026-07-25・Opus 5実施）のQ7-2。
  authoring計画とは独立の既存不具合として、カオス先輩が単発根治を裁定（案B＝既存経路も直す）。
- 施工場所: novel_mvpの家（WebUIフロントが主戦場）
- 位置づけ: 横断原則「無言失敗の根絶」の適用工事。新機能ではない。

## 1. 問題（調査報告Q7-2の要約）

WebUIのmdエディタ保存経路 `saveMdAndReturn()`（App.tsx:3375-3391）は
`saveEventMd` → `convertEvent` のみを呼び、音声差分適用
（`voiceEventsApplyDiff`）が結線されていない。結線済みなのはカード側
書き戻し経路 `afterWriteback()`（App.tsx:3290-3300）のみ。

結果（実測済み）: 台本mdを丸ごと差し替えて行がシフトすると、
旧音声ファイルが別の台詞に貼り付いたまま `has_audio=true` となり、
「変更分のみ生成」が黙ってスキップする。lint検査7も検出しない。
中身違いの音声で出荷しうる。

## 2. 目的と非目的

### 2-1. 目的

mdエディタ保存経路（丸ごと差し替え含む）でも、カード側経路と同等に
hash_diff → apply-diff（音声流用・陳腐化退避）が必ず走るようにする。
差分結果（流用・要生成・陳腐化）を保存後に画面表示する。

### 2-2. 非目的（スコープ外・混ぜるな）

- authoring工事のS2（inbox取り込み口）: 統合設計書側。本工事は既存経路のみ
- 版ズレ検知の小工事: 別玉（42番§2-6）
- hash_diff / apply-diff 本体のロジック変更: 現物は正しい（実測済み）。触らない
- カード側経路 afterWriteback(): 正常動作中。触らない

## 3. 設計原則（継承）

1. 既存API無改変が原則。結線はフロント側の呼び出し追加を基本とする
   （Step0調査でサーバ側の小改修が不可避と判明した場合は要裁定として停止）
2. 保存前の旧event.json退避（差分の比較元確保）を含める。既存の.bak退避機構は
   維持し、外さない
3. 変更なし保存（行シフトなし）では音声に一切影響を与えないこと
4. commit-per-step・回帰テスト付き・先輩実機確認・GPU排他相乗りは非交渉

## 4. Step分割

### Step0: 現物確認（実装なし）
- apply-diff API（app.py:620）の引数契約と、afterWriteback()の結線実装を精読
- saveMdAndReturn()に同等結線を足す際の差分（旧JSONの確保タイミング等）を特定
- 不明点・サーバ側改修の要否を申告してから Step1 へ

### Step1: 結線実装
- saveMdAndReturn() 経路に 旧版退避→保存→変換→hash_diff→apply-diff→結果表示 を結線
- フロント再ビルド（npm run build 明示実行）込み

### Step2: 回帰テストと検収
- 回帰3ケースを自動テスト化: ①行挿入でシフト（流用＋新規行のみ要生成）
  ②既存行の本文変更（当該行のみ要生成）③変更なし保存（音声無影響）
- 既存テスト全緑（現行246本）・カード側経路の無影響確認
- 先輩実機確認: 調査報告Q7-2の再現ケースをWebUI上で再演し、
  旧音声の貼り付きが起きないことを目視

## 5. 合格線

- Q7-2の実測ケース（先頭1行差し込み）で、新規行のみ「音声未生成」になり、
  シフトした既存行の音声が正しく流用されること
- 陳腐化した音声が上書きでなく退避されること（既存apply-diffの挙動どおり）
- 既存テスト全緑・カード側経路と変換済みJSONに挙動差なし
