# DES-0001 v1.2 差分改訂書

原則：**現物実装（novel_mvp・テスト147本緑・2026-07-22時点）が正**。
本書の各項は仕様文書を現物と実測に一致させる訂正であり、
現物側の挙動変更を伴わない（明記した予約項目を除く）。

## 訂正束（13件）

### 1. sidecar JSON記述の誤記訂正（39番持ち越し）
音声sidecar JSONの記述を、Irodori-TTS実装現物（音声ファイルごとに
同名sidecar JSONを併置する現行方式）に一致させる。v1.1の該当記述と
現物が食い違う箇所は現物を正として書き改める。

### 2. 立ち絵actor属性（予約フィールドとして正式化・実装はv2）
line stepに任意フィールド actor（発話中の立ち絵強調用・立ち絵ID参照）を
**予約**として定義。v1.2時点で書き手は使用可・全アダプタ/エンジンは
未消費（前方互換原則により無視）。消費実装はv2帳簿。

### 3. §5-1-3の誤記訂正
「##の後ろスペース必須」→ 正：**スペースなし・任意受理**
（アダプタは有無どちらも受理。裁定原則「mdは執筆者に優しく」準拠）。

### 4. option.set_flags の正式化
choiceの選択肢に set_flags を正式フィールド化（アダプタ実装済み）。
エンジン側（store-sim）の消費実装は**ゲーム側フェーズへ移管済み**
（41番§2）。未消費エンジンは前方互換で無視。

### 5. flag名の文字規約
snake_case縛りは**実ファイル対応ID**（event_id・画像ID・音声キー）のみ。
flag名はUTF-8語文字可（例: 覚悟・動揺——現物exportで実証済み）。

### 6. trigger文字列短縮形の明文化
フロントマター trigger の短縮形（実装済みの受理形）を仕様に転記し
正式化。完全形と短縮形の対応表を明記。

### 7. _kanji導出＝「個別実装制」と明文化（司令塔裁定）
_kanji派生の汎用導出機構は**存在せず、作らない**。kanji変数は
エンジン個別実装制（現行実在は play_days_kanji のみ・Main.gd手計算）。
lintは kanji_vars 表により「base実在・kanji未実装」をWARNING区別
（実測40番§2準拠）。汎用機構の新設はv2以降の別裁定事項。

### 8. 効果キー＝書き込み可能contract
apply等の効果で書き込み可能なキーは **money / debt / reputation /
flag** の4系のみ。game_vars.json（16変数）は**読み取り語彙**であり
書き込み対象ではない。writable_keys の契約ファイル化はv2検討
（v1.2は仕様本文明記まで）。

### 9. シーン内合流goto
シーン内合流はアダプタが正規化し、**gotoフィールドは出力しない**。
別合流点パターン（複数の非直後合流）は未対応であり、検出時は
アダプタが**停止する**取り決め（黙って誤変換しない）。

### 10. イベントJSON梱包形式（DEC-0007転記）
イベントJSONファイルの梱包形式は**トップレベル配列**。
単体オブジェクトは不正（EventLibrary読み込み拒否・2026-07-22の
開通誤認事故の根本原因）。梱包形式はスキーマと同格の契約事項。

### 11. D&D画像割当仕様（DES-0003工事D確定版の編入）
- 受け入れ：png/jpg/webp。他は明示エラー。巨大は警告付き受理
- 採番：元名ベースの小文字ASCII正規化（拡張子除去・空白/記号→_・
  連続_畳み込み）。**非ASCII含む場合は img_連番フォールバック**
  （既存走査の最小空き番号）。衝突は _2/_3 サフィックス
- 登録機構：**正しい場所に正しい名前で置くこと自体が登録**
  （ファイルシステムスキャン方式・別レジストリファイル不保持。
  mdが正・独自メタ不保持と同型の原則）
- 書き戻し：バックアップ退避→md ##舞台:行更新→再変換→整合確認。
  書き戻し失敗時は画像を消さず fully_applied:false ＋
  writeback_error で「格納済み・割当未反映」を明示（状態が嘘を
  つかない原則）

### 12. export＝共通中間形式の位置付け（原則の仕様昇格）
export一式（events/*.json・voice/*.ogg＋sidecar・images.json・
manifest.json）は**エンジン中立の共通中間形式**。エンジン対応は
外付けアダプタ方式（実在：Godot直読み／events_to_renpy。
Tyranoは旧経路レガシーでexport非対応・アダプタ新設はv2需要待ち）。
アダプタの合格線は**「出力契約の証明」まで**であり、受け側エンジンの
磨き込みはアダプタ工事のスコープに含めない（41番§2の教訓の恒久化）。

### 13. stage.slots の枠数と重ね順規約
- 枠数：**最大3（左・中央・右）を正式範囲**とする（v1.1の
  「1=中央/2=左右」から拡張。Ren'Pyアダプタで3枠写像実装済み・
  現物との平仄合わせ）。4枠以上は将来のconfig拡張のまま
- 重ね順：**slots配列順＝奥→手前**を正式規約とする（現行の
  show宣言順挙動の明文化・実装変更ゼロ）。発話者手前等の動的制御は
  actor属性（本書2）の消費実装とセットでv2
