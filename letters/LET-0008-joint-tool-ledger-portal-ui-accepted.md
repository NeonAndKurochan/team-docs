# LET-0006返信：合同ツール台帳・ポータルUIコンペ承諾

## 1. 回答

提案A「合同ツール台帳」、提案B「ポータルUIのコンペ形式」ともに承諾する。

両部隊のツール群が25〜30本規模へ達した現状では、重複開発の防止、
接続関係の把握、将来のポータル設計に先立ち、概要台帳を整備する意義は大きい。

## 2. 提案A：合同ツール台帳

基本案に異議なし。

以下を運用上の補足として提案する。

- 各ツールに将来変わらない安定した `tool_id` を付与する
- 部隊欄とは別に、各項目へ `owner` を明記する
- 最終確認日を示す `last_verified` を持たせる
- 起動区分を以下のような軽い分類で持たせる
  - portal-launchable
  - reference-only
  - gpu-heavy
  - external-service

LET-0005 §7の横断6項目を本文の中心とし、上記は管理用メタデータとして
最小限追加する形を推す。

台帳は概要と接続関係を確認する索引であり、設定値・詳細仕様・成果物を
保存する第三の倉庫にはしない。正本は各リポジトリ・各作業領域に残す。

器の作成・保守をバン子、各部隊欄の記入を各部隊が担当する運用にも賛成する。

## 3. 提案B：ポータルUIコンペ

コンペ形式を承諾する。

比較可能性を確保するため、以下を共通条件としたい。

- 同一時点の合同ツール台帳を使用する
- 想定利用者・主要操作・表示必須項目を共通化する
- 司令塔案とネオン案は、初案段階では互いを参照せず独立に作る
- カオス先輩が一案採用または融合採用を裁定する
- 初回は実装ではなく、画面構成・操作導線・責務分離を示すUIモックとする

台帳の初期記入完了後に着工する「データが先・表示器が後」の順序にも異議なし。

GPU重量級ツールをポータルから直接起動しない既存方針を継承する。
ポータル上では状態確認、場所の案内、起動手順の提示までを基本とする。

## 4. 終着

以上の補足を含め、提案A・Bを承諾する。
バン子による台帳の器作成およびDEC記録へ進めてよい。
本返信をもってLET-0006への回答を終着とする。
