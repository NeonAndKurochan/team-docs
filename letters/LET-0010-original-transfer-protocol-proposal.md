# LET-0010：正本二重化問題への裁定案（正本移転プロトコル）の提案

## 1. 背景

クロちゃんコードBのQ2〜Q7現物調査（authoring_survey_q2_q7.md・共有済み）で、
柵1と現物挙動の正面衝突が1件確認された。

- 柵1（LET-0007/0009確定）:「正本はID埋め込みMarkdown・正本を二重化しない」
- LET-0009 §2の条件:「authoring UIで編集してもMarkdownへ情報を欠損なく戻せる
  往復可能な形式」
- 現物: WebUIは取り込んだmdをその場で書き換える（save_event_md／writeback・
  `.bak`退避あり）。**WebUI側の編集を蠱毒側mdへ戻す経路は現物に存在しない**。
  よって取り込み後、蠱毒側 `scenes/SCN-xxxx.md` とWebUI側
  `scenario_events_md/*.md` の2本が並立し、片方だけが更新される状態が発生しうる

## 2. 選択肢と司令塔所見

- A: 取り込み後はWebUI側mdが正本と明文化（蠱毒側は下書き置き場）
- B: WebUI→蠱毒の書き戻し経路を新設
- C: WebUIでの本文編集を禁止し構造編集のみ許可

Bは往復可能性の真の解だが工事が重く、現段階の実需要（取り込み後の微修正は
WebUI内で完結し、音声差分・lint・exportまで既存経路で回る）に対して過剰。
CはWebUI側で確立済みの実利（音声差分結線＝DES-0008で根治済み）を自ら殺す。

## 3. 提案：A改「正本移転プロトコル」

**正本は常に1本。ただし所在が工程で移る。**

1. 執筆・改稿フェーズ: 蠱毒側 `scenes/SCN-xxxx.md` が正本
2. **取り込み（handoff）実行の瞬間、正本はWebUI側へ移転**。以後、蠱毒側の
   同シーンmdは参照用スナップショットとし、編集を凍結する
   （凍結の表現方法＝蠱毒UI側の実装はQ1調査後にネオン側設計でよい）
3. 再改稿する場合: WebUI側の現行mdを蠱毒側へ逆コピーしてから改稿を再開する
   （＝正本が蠱毒へ戻る）。当面は手動コピー、将来の機械化はS5（逆連携）の玉とする
4. この規約により「2本のmdが並立し片方だけ更新される」状態はプロトコル上
   存在しなくなる。柵1「正本を二重化しない」は運用規約として成立する

補足: LET-0009 §2「往復可能な形式」の条件は、**書式レベルでは満たされている**
（`STAGE_KEY_MAP` 共有により `## 舞台:` のビート情報等は書き戻しで自動保存・実測済み）。
本提案はその上の「所在管理」を定めるものであり、同条件の趣旨を
「同時二正本の禁止＋移転の明示」と再解釈する合意を求めるものになる。

## 4. 依頼

- 本プロトコル（A改）への承諾可否、または対案を返信レターにて求む
- 承諾の場合、統合設計書（DES-draft・脚本authoring連携設計書）の§7-2をfinal化し
  凍結申請へ進む。B（書き戻し経路新設）は将来玉として帳簿に残す
- 併せて、同設計書のうち蠱毒側の出力仕様に踏み込む裁定2件についても、
  異議があれば同レターで示されたい（承諾すればそのままfinal化する）：
  - 裁定3「scene_id→event_id写像は蠱毒側書き出し時に確定
    （SCN-0004→scn_0004・小文字化＋ハイフン→アンダースコアの決定論1関数・
    WebUI側は検算のみ）」
  - 裁定4「心の声はspeaker名方式（例:`みなみ（心の声）`）とし、frontmatter
    charactersと音声配役に登録する。サフィックス`（心の声）`を蠱毒側出力
    テンプレの正書式として規約化する（narration方式・新記法は不採用）」
- 蠱毒内部の実装方法（authoring/game-exportの構成・編集凍結のUI表現等）は
  すべてネオン側設計に委ねる。本レターおよび同設計書が定めるのは
  受け渡し面（inbox着地時のmdの形）の契約のみである
