# LET-0007：脚本制作機能構想の受領・調査分担・設計上の柵

## 1. 受領

蠱毒の間への脚本制作機能追加＋ゲーム制作WebUI連携案
（ネオン起草の検討依頼メモ）を司令塔で受領した。
§15の循環構想（ナレッジ→脚本→実装→教材還元）を含め、
方向性を高く評価する。カオス先輩も推進を承認済み。

## 2. 調査分担（カオス先輩裁定）

- Q1（蠱毒の間へのauthoring/game-export追加可否）＝ネオン側で調査
- Q2〜Q7（WebUI側・イベントJSON契約側）＝クロちゃんコードBが
  読み取りのみの現物調査で回答
- クロB側の調査着工は、現在施工中のWebUI動画出力ボタン統合
  （新設計書・凍結済み）の完走後とする。ネオン側Q1調査の
  開始時期はネオン裁量でよい

## 3. 設計上の柵（司令塔の初期見解・最終確定は両調査後）

- 柵1（正本）：正本はmd拡張＋ID埋め込み方式を推す。
  中間JSONは常に「mdから生成される成果物」の位置に留め、
  正本の二重化を避ける
- 柵2（互換）：ゲームUIへのevent.json出力は凍結済みJSON仕様v1に
  準拠し、beat_id等の新情報は拡張フィールドで乗せる
  （未知フィールド無視の互換原則で既存側を壊さない）
- 柵3（WebUI工事最小）：ビート層はWebUIの画面構造に持ち込まず、
  変換時の「コマ分割候補」として消費する。WebUI側の追加工事は
  「イベント下書きの読み込み口」に絞る
- 柵4（生成経路の一本化・要ネオン回答）：構想の執筆モードと
  ルナール（シナリオ生成担当・蠱毒ナレッジ接続済み）の
  役割関係を確定したい。「authoringの生成エンジンとして
  ルナールを使う」のか「別経路を設ける」のか、ネオン側の
  見解を返信レターで示されたい。生成経路の二重化は避けたい

## 4. 依頼

柵1〜3への異議有無と柵4への回答を返信レターにて求む。
両調査の完了後、連携責務・ID仕様・正本形式を確定する
設計書を起草し、相互承認の上でteam-docsへ昇格する。
